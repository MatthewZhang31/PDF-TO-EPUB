================================================================================
一、这是什么
================================================================================

一套可复用的流水线，把扫描版 PDF 书籍转成 EPUB 3。它解决的是扫描件特有的
三类问题：

  1. 文字脏。扫描件要么没有文本层，要么文本层是十几年前的 OCR 产物，标点符号
     系统性错认（把"。"认成"J"、把"："认成"厂"）。工具会重新 OCR，并做保守的
     标点修复。

  2. 结构丢。扫描件通常没有或只有粗糙的 PDF 书签。工具会用"印刷页码偏移量"从
     印刷目录页反推出每一章在 PDF 里的物理位置，重建可跳转的多级目录。

  3. 图表丢。表格和插图在扫描件里就是像素，文本提取拿不到。工具会按题注定位、
     按像素分析定位，把图表裁成图片插回正文原位。

交付物（每次转换都会产出）：

  <书名>.epub      成品电子书
  cover.jpg        从扫描件提取的封面
  toc.json/toc.md  恢复出的目录
  figures/         从书中裁出的表格与插图
  analysis.json    PDF 分析报告（模式、书签、逐页质量）
  book.json        清洗重建后的结构化正文
  epub_check.json  EPUB 结构校验结果


================================================================================
二、第一次在新电脑上配置
================================================================================

前置条件
--------------------------------------------------------------------------------
  - 已装好 DeepSeek Harness（DSH）
  - Python 3.10 或更高（3.11 / 3.12 最稳）

步骤
--------------------------------------------------------------------------------
  1) 克隆到 DSH 的用户级 skill 目录

     git clone https://github.com/MatthewZhang31/PDF-TO-EPUB.git `
       "$env:USERPROFILE\.dsh\skills\pdf-to-epub"

     注意：路径不能改。DSH 只从 $DSH_HOME\skills\（默认 ~\.dsh\skills\）
     发现 skill，放到别处命令行仍可用，但不会自动出现在会话里。

  2) 一键安装依赖 + 自检

     powershell -ExecutionPolicy Bypass -File `
       "$env:USERPROFILE\.dsh\skills\pdf-to-epub\install.ps1"

  3) 看到 "all checks passed" 和 "== ready ==" 即为成功。

不需要任何注册步骤。克隆完新开一个 DSH 会话，说一句"把这本书转成 EPUB"，
它会自动加载 pdf-to-epub 这个 skill。

安装脚本参数
--------------------------------------------------------------------------------
  -Mirror <url>     pip 镜像，默认清华 https://pypi.tuna.tsinghua.edu.cn/simple
                    换到国外网络可改 -Mirror https://pypi.org/simple
  -SkipInstall      跳过依赖安装，只做自检
  -SkipTest         跳过自检

依赖清单
--------------------------------------------------------------------------------
  pymupdf                  必需。解析 PDF、提取文本、渲染页面、读书签
  pillow                   必需。封面缩放与重编码
  numpy                    必需。OCR 与图表分析的图像缓冲
  rapidocr-onnxruntime     可选。PP-OCR 中文模型，纯 pip 安装、离线可用
  onnxruntime              可选。RapidOCR 的推理后端

  没有 OCR 依赖时，带文本层的 PDF 仍可转换；纯扫描件无法转换。


================================================================================
三、日常使用：转一本书
================================================================================

最简用法（推荐）
--------------------------------------------------------------------------------
  $env:PYTHONIOENCODING="utf-8"

  python "$env:USERPROFILE\.dsh\skills\pdf-to-epub\scripts\pdf2epub.py" all `
    --pdf "D:\books\某本书.pdf" `
    --out "D:\deepseek workingspace\pdf2epub\out\某本书"

  一条命令走完：分析 → 抽封面 → OCR（按需）→ 清洗重建 → 打包 → 校验。

  扫描件元数据常常是空的，所以建议显式指定书名和作者：

  python "...\pdf2epub.py" all --pdf "某本书.pdf" --out "out\某本书" `
    --title "人类的误测：智商歧视的科学史" `
    --author "[美] 斯蒂芬·杰伊·古尔德 著　柳文文 译" `
    --publisher "重庆大学出版社"

  注意：OCR 很慢（见 11 节实测），务必放后台跑，不要盯着等。

分步执行（需要中途检查或修目录时）
--------------------------------------------------------------------------------
  $S = "$env:USERPROFILE\.dsh\skills\pdf-to-epub\scripts\pdf2epub.py"

  python $S analyze  --pdf X.pdf --out OUT   分析，抽封面
  python $S extract  --pdf X.pdf --out OUT --pages 7-10 --dpi 220
                                             把指定页渲染成 PNG 供人工查看
  python $S ocr      --pdf X.pdf --out OUT --workers 6
                                             跑 OCR（按页缓存，可中断续跑）
  python $S assemble --pdf X.pdf --out OUT --chapters chapters.json
                                             清洗重建 + 章节切分
  python $S build    --pdf X.pdf --out OUT --title "..." --author "..."
                                             打包 EPUB
  python $S validate --epub OUT\某本书.epub  校验成品

  各阶段只通过 --out 目录里的 JSON 通信，所以任何一步都能单独重跑。

缓存与重跑规则（很重要）
--------------------------------------------------------------------------------
  analysis.json          每次 analyze / all 都会重写
  pages_embedded.json    第一次算完就复用
  ocr.json               按页缓存，已完成的页不会重算（除非 --redo）
  cover.json             记录封面取自哪一页、哪个 PDF
  book.json              每次 assemble 都会重写

  推论：改了代码后如果发现结果没变，多半是缓存没刷新。此时应重跑 all
  （或删掉对应的 JSON），而不是只重跑某一个阶段。

  另一条推论：换电脑时如果不想重跑 OCR，把整个 out\<书名>\ 目录拷过去即可，
  ocr.json 就是缓存。


================================================================================
四、参数速查
================================================================================

通用参数（所有子命令都有）
--------------------------------------------------------------------------------
  --pdf <路径>          输入 PDF（必填）
  --out <目录>          输出工作目录（必填）
  --title <文字>        覆盖书名
  --author <文字>       覆盖作者
  --lang <标签>         语言，默认 zh
  --publisher <文字>    出版方
  --date <文字>         日期
  --chapters <JSON>     手工指定目录，格式见第七节
  --text-source <模式>  auto / embedded / ocr，默认 auto
  --no-repair           关闭 OCR 标点修复
  --no-figures          不提取表格与插图
  --figure-dpi <整数>   图表裁切分辨率，默认 300
  --include-front-matter  把封面/版权/印刷目录页也放进正文流

仅在 ocr 和 all 上可用
--------------------------------------------------------------------------------
  --pages <范围>        限定 OCR 页码范围，如 "1-5,10,20-"
  --force-ocr           对所有页做 OCR，包括纯图片页
  --embedded-only       已有可用文本层的页不重跑 OCR（快速路径）
  --redo                忽略 OCR 缓存，强制重算
  --workers <N>         OCR 进程数，默认 min(4, CPU/2)
  --ocr-height <px>     OCR 渲染高度，默认 2200；小字号可提到扫描件原生高度

仅在 all 上可用
--------------------------------------------------------------------------------
  --skip-ocr            完全不跑 OCR，只用内嵌文本层（最快）
  --cover-page <页号>   手工指定用第几页当封面

仅在 analyze 上可用
--------------------------------------------------------------------------------
  --cover-page <页号>   手工指定封面页
  --no-cover            不提取封面

仅在 extract 上可用
--------------------------------------------------------------------------------
  --pages <范围>        要渲染成 PNG 的页
  --dpi <N>             渲染分辨率，默认 150

仅在 validate 上可用
--------------------------------------------------------------------------------
  --epub <路径>         要校验的 EPUB


================================================================================
五、六个阶段分别在做什么
================================================================================

analyze —— 判断这本书该怎么转
--------------------------------------------------------------------------------
  - 统计页数、页面尺寸、元数据
  - 逐页统计字符数、图片覆盖率、是否有乱码特征
  - 判定转换模式：
      text-layer      内嵌文本层可用（大多数老扫描件属于这类）
      garbled-layer   有文本层但基本是噪声，需要整本 OCR
      scanned         几乎没有文本层，需要整本 OCR
  - 读取 PDF 书签（outline）
  - 猜测封面页（第 1 页若是整页图片就用第 1 页）
  - 找印刷目录页（只在书的前 1/8 范围内搜索，避免正文里带编号列表的页面被误判）

cover —— 提取封面
--------------------------------------------------------------------------------
  把封面页按 200 dpi 渲染，缩放到 1600px 宽，存成 JPEG。
  不是从 PDF 里抽原始图片流——扫描件的封面常被切成几条或存成难处理的格式，
  重新渲染更可靠。

ocr —— 文字识别
--------------------------------------------------------------------------------
  两套文字来源，按页择优：

    OCR（RapidOCR / PP-OCR）：标点、中英混排准确率明显更高
    内嵌文本层：保存了脚注标记和页码，但标点是十几年前 OCR 的产物

  auto 模式优先用 OCR，再用行对齐把 OCR 丢掉的脚注标记（①②③）和项目符号
  （◎）从内嵌层回填；反过来，内嵌层还会纠正 OCR 把 ◎ 认成数字圈的错误。

assemble —— 清洗与重建
--------------------------------------------------------------------------------
  逐页处理：
    1. 剔除页眉页脚与页码（重复出现的短行 + 边距内的孤立数字）
    2. 把竖排书眉切掉（它贯穿整页，靠边距判断抓不到，必须按文本栏限制）
    3. 分离脚注区（字号明显小于正文、且位于页面下部的行）
    4. 修复跨行错序（同一视觉行被切成多个片段的情况）
    5. 合并成段落（按缩进、句末、居中、项目符号判断）
    6. 丢弃 OCR 噪声块
    7. 应用保守的标点修复规则
    8. 剔除与章节标题重复的首行
    9. 表格与插图：把图形区域的文字行移出正文，原位插入图片

  然后按章节骨架切分，同一页有多个目录条目时，只有一个占页，其余变成
  "导航项"指向它，避免该页正文重复输出。

build —— 打包
--------------------------------------------------------------------------------
  写出 EPUB 3：mimetype 必须是压缩包第一项且不压缩，然后是 container.xml、
  content.opf、nav.xhtml（EPUB 3 导航）、toc.ncx（给老阅读器的兼容）、
  样式表、封面页、每个章节一个 XHTML、以及所有图表图片。

validate —— 校验
--------------------------------------------------------------------------------
  把包内每个 XHTML / OPF / NCX 都当 XML 解析一遍，并解析每个文档内部的
  相对引用（link / img / svg image / a），核对目标文件确实在包里。
  结果写进 epub_check.json。

  历史上正是"只检查清单、不检查引用"让一个封面路径错误溜了过去：
  包完全合法，但封面显示为破图。


================================================================================
六、转换后必须做的检查
--------------------------------------------------------------------------------
流水线是确定性的，但几个判断必须由人（或模型）来做。转完请检查：

  1. 看 analysis.json 的 mode 和 garble_ratio。
     如果 garble_ratio 高但 mode 是 text-layer，改用 --force-ocr --text-source ocr。

  2. 看 toc.json。章节级条目如果有错或缺失，用 --chapters 手工修正后重建。

  3. 看 book.json 里最大章节的首段和末段。留意：串行错乱、残留页码、
     脚注粘连。

  4. 抽查渲染效果。提取 EPUB 后截图（预览页必须放在 OEBPS\text\ 下，
     因为 ../images/ 只从那一层解析得到）：

       python -c "import zipfile;zipfile.ZipFile(r'book.epub').extractall(r'%TEMP%\chk')"
       # 把 <figure>...</figure> 附近的内容存成 %TEMP%\chk\OEBPS\text\preview.html
       & "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" `
         --headless=new --screenshot="$env:TEMP\chk\fig.png" --window-size=800,1500 `
         "file:///$env:TEMP/chk/OEBPS/text/preview.html"

  5. 诚实报告残留的 OCR 错误。字符级误认（如"戈达德"被认成"戈这德"）无法用
     规则安全修正，不要用词典去"猜"，也不要说扫描件被完美转录。


================================================================================
七、目录（TOC）的处理
================================================================================

优先级
--------------------------------------------------------------------------------
  1. --chapters 指定的手工目录（永远优先）
  2. PDF 内嵌书签
  3. 印刷目录页 + 页码偏移量
  4. 整本变成一章（会给出警告）

没有 PDF 书签时怎么恢复目录
--------------------------------------------------------------------------------
  扫描件常常没有书签，但有印刷目录和页码。工具会：

    1. 在书的前部找"目录"标题页，只向其后的连续页延伸
    2. 从每页页边读出印刷页码（detect_folios）
    3. 统计出出现最多的"物理页 - 印刷页"差值，即偏移量
       例：物理 83 页印的是 73，物理 120 页印的是 110，偏移量 = +10
    4. 印刷目录里每条目的页码 + 偏移量 = 它在 PDF 里的物理页

  偏移量会先整表校验：如果太多条目落到的页面上找不到对应标题，就判定偏移量
  不可信，退回"在正文里搜索标题"。运行日志会说明走的是哪条路：

    printed folios on 273 pages -> page offset +10; 89 TOC rows, 3 indent level(s)

什么时候该手工转录目录
--------------------------------------------------------------------------------
  自动提取能用但不完美：OCR 会把标题认错，书眉文字如果和标题黏在同一行也会
  被带进来。判断标准是——章节级条目对不对。

  如果章节级条目有错，就把目录页渲染出来自己读，然后写 --chapters：

    python "...\pdf2epub.py" extract --pdf X.pdf --out OUT --pages 7-10 --dpi 220
    # 读 OUT\pages\page_0007.png … page_0010.png
    python "...\pdf2epub.py" all --pdf X.pdf --out OUT --chapters chapters.json

chapters.json 格式
--------------------------------------------------------------------------------
  [
    {"title": "第一章 导引", "page": 47, "level": 1},
    {"title": "数字的诱惑", "page": 103, "level": 2},
    {"title": "导语", "page": 103, "level": 3}
  ]

  要点：
    - page 是 PDF 的物理页号，不是书上印的页码。换算 = 印刷页 + 偏移量。
    - level 1/2/3 会形成多级导航。
    - 同一页有多个条目时，只有第一个占页，其余自动变成导航项。
    - 条目行必须按页号递增，否则生成器会报错拒绝（防打错）。


================================================================================
八、表格与插图的处理
--------------------------------------------------------------------------------
扫描版学术书最核心的内容往往在图表里。如果丢掉，表格的文字会变成一堆乱码
段落，插图则彻底消失。工具会从页面扫描图中裁出图表，插回正文原位。

两类图表，两套找法
--------------------------------------------------------------------------------
  第一类：有题注的（表2.1 / 图3.1）
    按题注定位。"这行到底是题注还是正文里提到图"用"图形邻接性"判断——
    题注紧贴自己的图形，引用则夹在正文中间。

    只用文本规则判断会出错，这点被真实数据打回过两次：
      - OCR 会吃掉标签后的空格："图3.1 比恩绘制"被识别成"图3.1比恩绘制"
      - 真题注经常引用其它图号："图6.7旋转图6.6中两条..."

  第二类：没有题注的（漫画、作者像、整页图版、跨页表格的后半部分）
    按像素找：渲染页面，遮掉 OCR 文字框，看剩下多少墨迹。
    区分度很大——真插图占页面 2%~47%，而普通文字页全部低于 0.35%，
    所以用 1% 作门槛非常安全。只扫描正文范围内的页，封面/书名/版权页除外。

裁切与插入
--------------------------------------------------------------------------------
  - 按 300 dpi 渲染（约等于扫描件原生分辨率，8pt 小字也清晰）
  - 横向限制在文本栏内，这是排除书眉的关键
  - 按实际墨迹收紧边界
  - 不加内边距：区域边界本来就是紧贴相邻题注的，加边距会把下一个表的题注
    印到这张图的下沿
  - 图形区域的文字行从正文移除；题注变成 <figcaption>（可选中的真实文字）
  - 表格单元格的字号比正文小，脚注分割器会先认领它们，所以脚注区也要过滤

运行日志会说明找到了什么：

  figures: 45 cropped (6 tables, 5 artwork, 34 captioned figures) from 39 pages

相关参数
--------------------------------------------------------------------------------
  --no-figures          完全不提取
  --figure-dpi <N>      裁切分辨率


================================================================================
九、常见问题与排查
================================================================================

9.1 中文输出崩溃
--------------------------------------------------------------------------------
  症状：UnicodeEncodeError: 'gbk' codec can't encode character
  原因：Windows 控制台默认 cp936
  处理：每次调用前执行 $env:PYTHONIOENCODING="utf-8"

9.2 ModuleNotFoundError: No module named 'p2e'
--------------------------------------------------------------------------------
  原因：没有用绝对路径调用脚本
  处理：始终用 pdf2epub.py 的完整路径，或在自己的脚本里把
        ...\scripts 加进 sys.path

9.3 pip install 卡住然后超时
--------------------------------------------------------------------------------
  原因：默认 PyPI 索引在国内网络不可达
  处理：加 -i https://pypi.tuna.tsinghua.edu.cn/simple

9.4 一堆重复的 "OCR N pages with M workers" 然后 RuntimeError
--------------------------------------------------------------------------------
  症状：An attempt has been made to start a new process before...
  原因：Windows 的 multiprocessing 用 spawn，会重新导入入口模块。
        如果入口模块有未保护的顶层代码，子进程会再开子进程，无限递归。
  处理：杀掉残留 python 进程，只通过 pdf2epub.py 调用（它的入口有保护），
        或加 --workers 1

      Get-Process python -ErrorAction SilentlyContinue | Stop-Process -Force

9.5 OCR 比预期慢很多
--------------------------------------------------------------------------------
  速度取决于像素量和文字密度，不是页数。
  2200px 渲染的稀疏 19pt 书约 1.3 秒/页；
  2530px 原生分辨率的密集 9pt 书约 10 秒/页（444 页 = 74 分钟）。
  处理：先用 2200；只有小字号或识别效果差时才提高 --ocr-height。
        同时确认没有别的重活占着 CPU。

9.6 EPUB 是一整章
--------------------------------------------------------------------------------
  原因：没有书签，且印刷目录页没被识别出来
  处理：看 analysis.json 的 toc_pages。若确实没有，用 --chapters 手工指定。

9.7 章节起点早一页或晚一页
--------------------------------------------------------------------------------
  原因：扫描件的书签常有 ±1 页误差
  处理：用 --chapters 手工修正

9.8 封面是书名页或条形码
--------------------------------------------------------------------------------
  处理：--cover-page 1

9.9 封面在阅读器里不显示
--------------------------------------------------------------------------------
  先排查相对路径。cover.xhtml 位于 OEBPS\cover.xhtml，应引用 images/cover.jpg；
      ../images/cover.jpg 只在 OEBPS\text\ 下的文档才正确。
  validate 现在会解析文档内部的所有引用，路径错会直接报出来。

  如果路径没问题但 WPS 等阅读器仍不显示：EPUB 3 用 properties="cover-image"，
  老阅读器用 <meta name="cover">，两者工具都会写。封面页还额外用了整页 SVG
  包裹（Calibre / Sigil 等普遍采用的写法），兼容性最好。

9.10 排版里出现"【第二章】"或零散的"具""的"等字
--------------------------------------------------------------------------------
  原因：竖排书眉。它位于页面外侧、贯穿整页高度，靠"边距带内的重复行"判断
        抓不到，其单字会被并进正在构建的段落。
  处理：正文行会被限制在文本栏内（已内置）。若换书仍出现，说明该书文本栏
        边界与全局边距差异较大，需要在 clean.py 的 text_column 调整 slack。

9.11 图表被排到整章末尾，或题注出现两次
--------------------------------------------------------------------------------
  原因：图表块与段落是分开收集的，丢了顺序；或题注既做了段落又做了 figcaption
  处理：均已修复。图表位置在 build 阶段按块顺序输出，题注只作为 figcaption。

9.12 竖排题注的图表出现重复或裁成空白
--------------------------------------------------------------------------------
  原因：竖排题注的长宽比与横排相反，且贯穿图形全高，用横排题注的几何假设
        会把图形区域算到上方空白处。
  处理：已内置判据 _is_vertical_line()，遇到竖排题注就交给像素分析处理。

9.13 git push 报连不上 github.com
--------------------------------------------------------------------------------
  症状：Failed to connect to github.com port 443 或 Connection was reset
  说明：不是凭据问题。这类网络下 TCP 可能通但 TLS 被重置，而 DNS 常常只返回
        一个被封的 IP（固定 IP 无效，因为阻断跟随 SNI 而不是地址）。
  处理：先找本地代理。Clash / V2Ray / sing-box 之类常常在跑：

      Get-NetTCPConnection -State Listen |
        Where-Object { $_.LocalPort -in 7890,7891,7897,1080,10808,10809 } |
        Select-Object LocalPort, OwningProcess

      然后让 git 走它（只影响本仓库，不会提交）：

      git -C <repo> config http.proxy http://127.0.0.1:7897

  警告：不要把 push 走公网的 GitHub 加速镜像，那会终止 TLS，凭据会暴露。

9.14 换电脑后结果和旧电脑不一样
--------------------------------------------------------------------------------
  检查两件事：
    - 是不是少了本地未提交的改动
    - 是不是把旧的 out\ 目录带过去了（缓存会让结果保持旧版本）
  要复现完全一致的结果，从空的 out\ 目录开始跑。

9.15 阅读器里正文有重复段落
--------------------------------------------------------------------------------
  症状：epub_check.json 的 chapters 数远大于 toc.json 里的顶级章节数
  原因：book.json 往返时丢了 nav_only / href 字段，导致所有子条目都变成独立
        章节，同一页正文被输出多次。
  处理：已修复。给 Chapter 加字段时，务必同时改 to_dict() 和
        pdf2epub.py 里的重建代码。自检覆盖了这个往返。


================================================================================
十、已知限制
--------------------------------------------------------------------------------

  - 字符级 OCR 误认无法用规则安全修正（如"三个白人"被认成"三个自人"、
    "陷入"被认成"陷人"）。工具不会用词典去猜，这类错误需要人工校对。

  - 页面中间的各级小标题不会被识别成标题样式。扫描件抹平了字号与粗体信息，
    实测字号、粗体标志、墨迹密度三种信号都不可靠。它们在导航里能跳转，
    但在正文里和段落连排。

  - 无题注图表检测按横向墨迹带裁切。同一页上左右并排的多个图形会被裁成
    一张图。

  - 竖排文本、真正的多栏混排、复杂表格结构不处理。

  - 整页图版会按整页裁切，效果正确；但"上半页文字、下半页图"的版式只会裁
    下半页。

  - 目录页检测可能失手，此时整本书会退化成单章，需要 --chapters。

  - 封底推荐语、书脊这类艺术字体页面 OCR 质量差，可用 --chapters 剔除。

书 A：《齐泽克的笑话》（河南大学出版社 2016，177 页 ABBYY 扫描，简体中文）
--------------------------------------------------------------------------------
  有 PDF 书签（12 条），省了目录恢复这一步。

  分析        mode=text-layer，173/177 页有文本，乱码页仅 2 页（1.2%）
  封面        自动选中第 1 页（漫画头像版正式封面）
  OCR         2200px、4 进程，177 页约 4 分钟（约 1.3 秒/页）
  重建        8 个正文章节，533 段，75 个脚注块，6.2 万字符
  图表        2 幅无题注插图（p154 漫画、p176 作者像）
  成品        1.57 MB，18 个条目，22 个内部引用全部解析，0 问题

书 B：《人类的误测：智商歧视的科学史》（重庆大学出版社，444 页，9pt 密排）
--------------------------------------------------------------------------------
  没有 PDF 书签，没有书名/作者元数据。

  分析        mode=text-layer，438/444 页有文本，乱码 0%，正文 9pt，书签 0 条
  目录恢复    目录页 [7,8,9,10]；273 页读出印刷页码；偏移量 +10（244 页佐证）
  目录复核    自动条目可用，但章节级被 OCR 破坏，人工读目录页转录为
              chapters.json（13 章 + 33 节 + 57 小节）
  OCR         2530px（原生）、6 进程，438 页共 74 分钟（约 10 秒/页）
  重建        85 个正文节 + 18 个导航子条目，3258 段，37.8 万字符
  图表        45 个（6 个表格、5 幅像素检测出的插图、34 个有题注的图表）
  成品        8.6 MB，138 个条目，237 个内部引用全部解析，0 问题

  这本书暴露并修掉了四个缺陷：
    - book.json 往返丢字段，导致正文重复 1.8 万字符
    - 封面页相对路径写错，包合法但封面是破图
    - 竖排书眉混进正文，多出 412 个假段落、约 6500 字符噪声
    - 表格单元格漏进脚注，22 个乱码脚注块

性能规律
--------------------------------------------------------------------------------
  OCR 速度取决于像素量和文字密度，不是页数：

    渲染高度    页面高度    文字密度              进程数   实测
    2200 px     1007 pt     约 300 字符/页 19pt    4       1.3 秒/页
    2530 px     606 pt      约 900 字符/页 9pt     6       10 秒/页

  也就是说密集的 9pt 书比稀疏的 19pt 书慢约 8 倍。估算时看 analysis.json
  里的 page_size 和 body_font_size，不要看页数。

  除 OCR 外的所有阶段都很快：444 页的 assemble + build 约 5 秒。

十三、术语对照
--------------------------------------------------------------------------------
  文本层          扫描件里附带的、由 OCR 生成的隐形文字（可选中、可搜索）
  物理页          PDF 里的第 N 页
  印刷页          书上印的页码
  偏移量          物理页 - 印刷页，全书恒定
  页眉/书眉       每页重复出现的书名或章节名
  页码/folio      每页边上的数字
  题注/caption    表格或插图旁的编号与说明文字
  导航项          目录里有条目、但不单独占文件的层级（指向所属章节）
  文本栏          正文所在的横向范围，栏外是书眉与页码
